## 1. 问题陈述

AI harness（ZCode、Claude Code 等）缺少与 Obsidian vault 之间的通道：无法直接浏览、搜索、编辑 vault 中已有笔记，也无法把生成的内容作为笔记写入 vault。本项目实现一个 MCP server，把 vault 暴露为一组标准 MCP 工具，让任意支持 MCP 的 harness 都能读写 Obsidian 文档。

## 2. 目标用户

- 个人知识管理者：在 Obsidian 中维护笔记，同时用 AI harness 日常办公，希望 AI 能直接检索和整理自己的 vault。
- AI harness 用户：希望把 AI 生成的内容（总结、日记、笔记）沉淀到 Obsidian，而不是散落在对话里。

## 3. MVP 功能列表

> 每条功能必须有可验证的验收标准。不在此列表中的功能不做。

| 编号 | 功能名称 | 描述 | 验收标准 |
|------|---------|------|---------|
| F01 | vault 浏览 | 列出 vault 根目录或指定子目录下的笔记与文件夹 | 调用浏览工具返回该目录的 `.md` 文件与子文件夹列表；空目录返回空列表 |
| F02 | 读取笔记 | 读取指定笔记的完整 Markdown 内容（含 frontmatter 原文） | 对已知笔记调用读取工具，返回内容与磁盘文件逐字一致 |
| F03 | 搜索笔记 | 按关键词全文搜索，可限定目录范围 | 在含关键词的 vault 上调用搜索工具，返回命中文件路径与匹配行；无匹配返回空列表 |
| F04 | 创建笔记 | 在指定路径创建新笔记，可携带初始内容 | 调用创建工具后，目标路径存在新文件且内容一致；重复路径默认报错 |
| F05 | 编辑笔记 | 对已有笔记整体覆盖、末尾追加、或精准替换文本片段 | 调用后文件按预期变化；替换片段未命中或多处匹配时报错且文件不变 |
| F06 | 整理笔记 | 重命名、移动、删除笔记 | 重命名/移动后原路径不存在、新路径存在；删除后文件出现在 vault 根 `.trash/` 下而非永久丢失 |

## 4. 非目标（明确不做什么）

- Canvas/画布与二进制附件（`.canvas`、图片、PDF 等）：用户明确排除，MVP 只处理 Markdown 文本。
- 第三方插件集成（Dataview、日记、日历等插件的语法与数据）：用户明确排除。
- 同步/发布到网络（Obsidian Publish、多端同步等）：与本地文件管理定位无关，默认排除。【假设】
- tags/frontmatter 专门管理（标签索引、按标签过滤查询）：frontmatter 属于文本内容，可随 F05 编辑工具自然修改，但不提供专门的元数据 API。【假设】
- Obsidian Local REST API / URI 接入：接入方式已定为直接文件系统（见 decisions.md D001）。

## 5. 边界与异常

> 每个 MVP 功能的异常路径与期望行为，E 编号供任务和测试引用。Phase 5 按本节逐条检查。

| 编号 | 所属功能 | 异常场景 | 期望行为 |
|------|---------|---------|---------|
| E01 | 全部 | `OBSIDIAN_VAULT_PATH` 未设置或指向不存在的目录 | server 启动即报错退出/调用返回明确错误，提示如何配置 |
| E02 | F02/F05/F06 | 目标笔记不存在 | 返回 not found 错误，不隐式创建文件 |
| E03 | F04 | 目标路径已存在同名笔记 | 默认报错；显式传 `overwrite=true` 才覆盖 |
| E04 | F05 | 替换片段未找到，或匹配多处 | 返回错误说明原因（未找到/命中 N 处），文件内容不变 |
| E05 | 全部 | 请求路径越出 vault 根（`..`、绝对路径逃逸） | 拒绝操作，返回路径非法错误，不做任何文件改动 |
| E06 | 全部 | 请求对象不是 Markdown（`.png`、`.canvas` 等） | 拒绝并提示仅支持 `.md` 文件 |
| E07 | F06 | 删除笔记 | 默认移入 vault 根 `.trash/`（Obsidian 原生兼容），提供 `permanent` 参数才永久删除 |
| E08 | F06 | 重命名/移动的目标位置已存在文件 | 报错且原文件保持原位不动 |
| E09 | F03 | 搜索无任何匹配 | 返回空列表，不视为错误 |

## 6. 技术约束

- TypeScript 5.x（strict）+ Node.js ≥ 20，npm 包管理。
- MCP stdio transport，可被任意 MCP 客户端以 `node`/`npx` 命令拉起。
- vault 根路径仅来自环境变量 `OBSIDIAN_VAULT_PATH`，不硬编码。
- 兼容 Windows 路径（开发与使用环境为 win32）。
- 所有文件操作限制在 vault 根目录内（安全不变量，见 E05）。
- 读写统一 UTF-8。

## 7. 假设与依赖

- 假设：用户已有本地 Obsidian vault，并能提供其绝对路径用于配置。
- 假设：「同步/发布」与「tags 专门管理」默认排除（访谈未逐一确认，记录于此，可随时修订）。
- 依赖：MCP 客户端（ZCode / Claude Code 等）支持 stdio MCP server 配置。
- 依赖：`@modelcontextprotocol/sdk` 官方 TypeScript SDK。
